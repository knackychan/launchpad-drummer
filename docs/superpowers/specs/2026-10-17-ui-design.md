# Launchpad Drummer — UI Design (Part 1, with room for Parts 2–4)

Date: 2026-10-17
Status: draft, awaiting user review
Parent spec: `2026-10-17-drum-sampler-design.md` (section 8 lists the UI parts, section 14 later parts)
Reference mockup: `docs/mockups/ui-mockup.html` (clickable, single file; open it in a browser)

This document locks the UI design before Plan 1B (Tauri + Svelte app) is written. Where it
and the mockup disagree, this document wins; fix the mockup.

## 1. Decisions (from the brainstorming session)

| Topic | Decision |
|---|---|
| Visual direction | Hardware skeuomorphic, everything: matte black plastic body, rubber pads with LED glow, Launch Control XL-style knobs/faders, recessed glass "LCD" screens for text-heavy areas, rack units with screws on Setup. Dark only. |
| Layout | One console window. Left rail of lit mode keys (PLAY / MIX / TRAIN / GAMES / BAND / SETUP), centre bay swaps per mode, top strip (set LCD, undo/redo, notice LCD), bottom status strip. |
| Grid mirror | Always the live LED state (same as the hardware). Selected pad = white bezel (screen only). Stored colour shown in the pad editor. |
| Bank switching | As on the hardware: 8 round side buttons right of the grid (top = bank 1, active lit white) + LCD scribble strip with bank name per button. |
| Pad editor | Fixed right-hand glass screen on Play. |
| Sample browser | Left glass screen on Play, foldable to a 28 px spine (Ctrl+B). |
| Mixer | Own MIX screen, a 1:1 Launch Control XL mirror + master. No level meters (would need new engine events; deferred). |
| Onboarding | "Power-on" LCD (NEW SET / OPEN SET + device lamps) only when no set can be opened. No Launchpad never blocks: notice + on-screen grid works. |
| Undo | Yes, 50 steps, kit edits only (new scope vs. parent spec; UI/router keeps the history). |
| Train (Part 2) | Same console; lanes on one big glass display, notes are glowing LED blocks. |
| Minimum window | 1280×720 logical px (covers 1920×1080 at 150 % scaling). Parent spec said ~1280×800. |

Additions to the parent spec that this design introduces (all approved in session):
undo/redo; a MIDI LEARN list in Setup (only way to remove a parameter binding); New/Open
set UI; "couldn't save" notice (router must report save errors); sample-name label on pads;
hardware pad hit also selects the pad on screen.

Not included (ask before adding): browser search box, level meters, pickup/soft-takeover
for LCXL, Save As / move set, light theme.

| `--line` | `#26282b` | separators |
| `--glass` | `#0b0e10` | screens / LCDs |
| `--lcd` | `#dbe7ea` | LCD text |
| `--lcd-dim` | `#7d8b90` | secondary LCD text |
| `--silk` | `#8b9096` | printed (silkscreen) labels |
| `--led-off` | `#3a3c3f` | unlit indicator |
| `--ok` / `--warn` / `--error` | `#3ddc84` / `#ffb020` / `#ff3b30` | lamps, notices, SOLO (green), MUTE (amber) |

**LED → screen colour.** Pad colours are Launchpad RGB 0–63. Screen value per channel =
`round(255 × (v/63)^0.6)` (low LED values look brighter, as real LEDs do; tune the exponent
by eye against the hardware). The pad colour picker only produces 0–63 values, so every
colour is valid on the device by construction.

**Preset swatches (16, LED values):** `63,0,0` `63,20,0` `63,40,0` `63,63,0` `30,63,0`
`0,63,0` `0,63,25` `0,63,63` `0,30,63` `0,0,63` `25,0,63` `45,0,63` `63,0,63` `63,10,30`
`63,63,63` `63,45,30`. **Row defaults** for newly imported pads (row 1 bottom → 8 top):
presets 1, 2, 4, 6, 8, 10, 12, 14 (red, orange, yellow, green, cyan, blue, purple, pink).

| Material | Recipe |
|---|---|
| Body | `--body` + 3 % fractal noise; 1 px top highlight `rgba(255,255,255,.06)` |

| Glass screen | `--glass`, inset shadow `0 2px 8px rgba(0,0,0,.9)`, faint 160° reflection gradient, radius 6 |
| Rubber pad | unlit `#25272a→#1b1d1f`, radius 6; lit = radial LED fill (centre mixed toward white) + outer glow of the colour at 45 %, size 0.4 × pad |
| Key | rectangular rubber, radius 4, 2 px bottom lip; lit = white text glow; latching colour variants amber / green / red |
| Round button | 26 px circle (side/top buttons); active bank = white lit |
| Knob | LCXL cap: dark radial cap, black skirt, white pointer line; ±135° travel |
| Fader | 6 px slot, 18 px black cap with white line, printed ticks +6 / 0 / −12 / −40 / −∞ |
| Rack unit (Setup) | plate + 4 screws |

### 2.3 Type

Two OFL families bundled as woff2 (no runtime fetch):
- **Barlow Semi Condensed**: silkscreen labels 10 px / 600 / uppercase / +0.08 em; body and
  list text 12–13 px.
- **JetBrains Mono**: all LCD values, tabular numerals. 11–13 px values, 16 px pad-editor
  title, 22 px power-on title.

### 2.4 Spacing, radii, motion

4 px base: 4 / 8 / 12 / 16 / 24 / 32. Radii: pad 6, key 4, screen 6, plate 10.
Motion: UI only animates what state events say (LEDs ~30 Hz), plus 60 ms key press/hover.
No decorative animation.

## 3. Shell (all modes)

```
┌ native Windows title bar ─────────────────────────────────────────┐
│ [SET ▸ My Kit ▾] [↶][↷]  [ notice LCD ……………………………… action  +n ] │ 40 px
├──────┬─────────────────────────────────────────────────────────────┤
│ PLAY │                                                             │
│ MIX  │                 centre bay (mode content)                   │
│ TRAIN│                                                             │
│ ░░░░ │  ░░ = blank cap (not fitted yet)                            │
│ ░░░░ │                                                             │
│      │                                                             │
│ SETUP│                                                             │
├──────┴─────────────────────────────────────────────────────────────┤

└────────────────────────────────────────────────────────────────────┘
```

- **Window**: native title bar (snap layouts, accessibility). Min 1280×720 logical.
- **Top strip**: set LCD (name; ▾ menu New set… / Open set… / Show in Explorer), Undo /
  Redo keys (unlit when nothing to undo), notice LCD (section 7).
- **Mode rail (80 px)**: 64×48 keys. Active lit white. Order PLAY, MIX, TRAIN, GAMES, BAND,
  gap, SETUP. Unbuilt parts are **blank caps** (no print, `aria-disabled`, tooltip
  "Part N — not fitted yet"). In Part 1, TRAIN, GAMES and BAND are blank.
- **Status strip**: lamps LAUNCHPAD and LCXL (green connected / off absent / amber port busy /
  red bootloader), AUDIO (green running / amber dropout in last 10 s / red stopped), audio
  LCD `backend · buffer · latency`, DROPS count, set path (middle-truncated), save LED (dim =
  pending, green blink on save, red = save failed). Clicking any lamp opens SETUP.

## 4. Play screen

Three bays: **browser (248 px, or 28 px folded) | Launchpad panel (auto) | pad editor
(≥ 290 px, takes extra width)**. Gaps 12 px.

### 4.1 Launchpad panel

- Top row: 8 round buttons as on the hardware. Only the last (Mixer, CC 111) is live =
  **STOP ALL** (tooltip "Stop all · Esc"); others dim, not focusable.
- 8×8 rubber pads, live LED colours. **Pad size** = `clamp(52px, min(fit-width, fit-height),
  80px)`, gap 5 px. At 1280×720 pads are ~55 px.
- Pad label: sample name, 8.5 px uppercase, white 78 % with dark shadow, bottom-left,
  truncated. Empty pad: unlit, faint `+` on hover. Missing sample: blinks red (from LED
  state) + `!` glyph.
- **Mouse**: press = play **and** select; release ends a hold-mode pad. Right-click menu:
  Learn MIDI note…, Clear pad, Show sample in Explorer.
- **Hardware pad hit** also selects that pad on screen.
- Selection = 2 px white bezel, 3 px offset.
- Side buttons + **scribble strips** (78 px LCD, same row height as pads): bank name; active
  bank bright, empty banks dim, red dot if the bank has missing samples. Click = switch.
  Double-click (or F2) = rename inline, max 16 chars, Enter commits, Esc cancels.
  Hardware side button switches the screen too.

### 4.2 Bank strip (plate under the Launchpad panel)

`BANK n LIGHTS` · FLASH / PLAY / RIPPLE latching keys (lit = on) · HUMANIZE knob
0–6 dB (readout `±x dB` = half the amount; `OFF` at 0).

### 4.3 Pad editor (glass screen)

Top to bottom:
1. Header: `R4·C2` (row from bottom, col), sample name 16 px, `0.45 s · 44.1 kHz`.
2. Missing sample: red box `Sample missing: samples/…` + LOCATE… (file picker, re-imports).
3. SAMPLE · TRIM: waveform ~full width × 72 px, coloured in the pad colour, region outside
   the trim dimmed; white start/end handles (drag, 8 px hit zone, min 10 ms apart); click
   elsewhere = audition the pad. LCD `START x ms   END y ms`.
4. COLOUR: LED values readout, 16 preset swatches (8×2, current has white ring), `+RGB`
   key opens three mini knobs R / G / B (0–63, integer).
5. VOLUME knob (−∞ … +6 dB; −60 shows −∞), PITCH knob (±24 st, 1 st steps, Shift 0.1),
   MODE two-position switch ONE-SHOT | HOLD.
6. CHOKE: key row OFF, 1–8. MIX GROUP: key row 1–8, current group name shown on the right.
7. MIDI: LEARN key (lit amber while waiting); when bound, LCD `NOTE 36 · device` + × to clear.

Empty pad: header shows `EMPTY` and the text "Empty pad. Drop a sample here, drag one from
the browser, or press Enter on a file in the browser." The editor screen is itself a drop
target for the selected pad.

### 4.4 Sample browser (glass screen)

Header: fold key ◀, library path LCD, FOLDER… key. Tree of folders and audio files (wav,
aiff, flac, mp3, ogg) in mono 12 px, 22 px rows. Click a file = audition (♪ marker).
Keyboard: ↑/↓ move, →/← open/close folder, Space = audition (or toggle folder), Enter =
load into the selected pad (keyboard alternative to drag and drop). Folded: 28 px spine
"▸ BROWSER".

### 4.5 Knobs (everywhere)

Vertical drag (150 px = full range; Shift = 10× finer), wheel steps, double-click = default,
arrows when focused (Shift fine), Home/End = min/max, right-click = Learn MIDI CC / Reset.
Value shown in an LCD under the knob. Faders: same, drag along the slot.

## 5. Drag and drop

Sources: Explorer files, browser files, pads. Targets: pads, pad editor (= selected pad),
side buttons / scribble strips (hover only).

| Drag | Drop on | Result | Target tag |
|---|---|---|---|
| Explorer/browser file | empty pad | copy to `samples/` (clash → `-2`, `-3`…); defaults: row colour, 0 dB, 0 st, ONE-SHOT, no choke, mix = row | IMPORT |
| Explorer/browser file | filled pad | replace sample, reset trim; keep colour, volume, pitch, mode, choke, mix | REPLACE |
| several files | pad | target pad, then next **empty** pads in reading order (right, then the row above); leftovers dropped with notice "n files not imported — bank full" | IMPORT ×n |
| pad | empty pad | move (all params) | MOVE |
| pad | filled pad | swap | SWAP |
| pad + Ctrl | any pad | copy (overwrites a filled target) | COPY |
| anything | side button / scribble strip held 400 ms | switch to that bank, drag continues | — |
| non-audio file or folder | anywhere | not-allowed cursor, red bezel on hovered pad, notice "Not an audio file" | — |
| anything | outside targets, or Esc | cancel (no drag-to-delete) | — |

Rules: 4 px threshold (below = click). A pad drag starts after the press has sounded; hold
voices are released when the drag starts. Feedback: ghost = small pad in source colour +
name; target gets a dashed white bezel + LCD tag. MIDI-learn bindings follow the sound on
move/swap; copy does not duplicate the binding. Every drop = one undo step (an undone import
leaves the copied file in `samples/`).

**Implementation constraint:** Tauri 2 intercepts native file drops, so Explorer drops come
from the window drag-drop event (paths + position, hit-tested against pad rects). Internal
drags use pointer events, not HTML5 DnD.

## 6. MIX screen

A Launch Control XL drawn as a plate: row labels column, 8 group columns (~98 px), bezel
gap, MASTER column.

Per column, top to bottom: scribble LCD `n NAME` (double-click / F2 rename, max 12 chars,
stored uppercase) · PAN knob (`L50…C…R50`) · PITCH knob (±12 st) · LOW-PASS knob (200 Hz–
20 kHz log, 20 kHz = `OFF`) · fader 200 px (−∞…+6 dB, 0 dB at 75 % travel) · dB LCD ·
MUTE (amber when on) · SOLO (green when on). MASTER: fader + LCD only.

Fader law (UI ↔ dB): `p ≥ 0.75: dB = (p − 0.75)/0.25 × 6`; `p < 0.75: dB = 40·log10(p/0.75)`;
`p = 0: −∞`.

Hardware LCXL moves update the screen at ~30 Hz. A screen change leaves the hardware control
out of step until it next moves, then the value **jumps** to the hardware (no pickup).

## 7. States, notices, onboarding

### 7.1 Notice LCD

One slot; shows the highest-priority active notice; `+n` key opens a popover listing all.
Icon + text coloured by level (✖ error red, ⚠ warn amber, • info grey, ✓ ok green).
`aria-live` polite, assertive for errors.

Priority (highest first):

| # | State | Lamp | Text | Action |
|---|---|---|---|---|
| 1 | MIDI learn armed | — | "Move a control on any MIDI device · Esc cancels" (pads: "Hit a key or pad…") | — |
| 2 | Audio device lost | AUDIO red | ✖ Audio device lost | RECONNECT |
| 3 | Set loaded from backup | — | ⚠ set.json unreadable — loaded backup (saved hh:mm) | DISMISS (stays until dismissed) |
| 4 | Save failed | save LED red | ✖ Couldn't save set — {reason}. Retrying | — |
| 5 | Launchpad bootloader | LAUNCHPAD red | ✖ Launchpad in bootloader — run Novation's MK2 updater, then replug | HOW TO FIX (popover with steps) |
| 6 | Launchpad port busy | LAUNCHPAD amber | ⚠ Launchpad port busy — close Components, DAWs or another copy of this app | — |
| 7 | Samples missing | — | ⚠ n samples missing | SHOW (selects next missing pad, switches bank) |
| 8 | ASIO unavailable | — | ⚠ ASIO not available — using WASAPI | DISMISS |
| 9 | Dropout in last 10 s | AUDIO amber | ⚠ Audio dropout — raise buffer size | SETUP |
| 10 | LCXL port busy | LCXL amber | ⚠ Launch Control XL port busy — close other MIDI apps | — |
| 11 | Confirmations (import, learn bound, undo) | — | ✓ text, 3 s | — |
| 12 | Launchpad disconnected | LAUNCHPAD off | Launchpad not connected — checking every 2 s | — |
| 13 | LCXL disconnected | LCXL off | Launch Control XL not connected — checking every 2 s | — |

Disconnected / busy / bootloader never block: the on-screen grid and MIX screen keep working.
Audio lost: pads still light, hits silent.

### 7.2 Power-on LCD

Shown in the centre bay (rail and status strip stay) on first run, when the last set folder
is gone ("Last set not found: {path}"), or when `set.json` and backup are both unreadable
("Couldn't open {name} — set.json and backup are unreadable. Files left untouched.").
Content: title, status line, lamps LAUNCHPAD / LCXL / AUDIO, keys NEW SET (folder picker,
default `Documents\Launchpad Drummer\`) and OPEN SET. While shown, MIX is disabled; PLAY
shows this screen; SETUP works. Otherwise the app reopens the last set.

### 7.3 Backend requirements implied by the UI (for Plan 1B)

- Router reports save errors (for notice 4 and the save LED).
- Router emits "dropout happened" events with a timestamp (10 s amber window).
- Undo history lives in the UI or router; covers set edits: pad params, sample replace,
  move/swap/copy, clear, bank names, light modes, humanize, group names, learn bindings.
  **Not** mixer values (from screen or LCXL).
- Audition plays a file once through the master bus, not through a pad.

## 8. SETUP screen

Single column of rack units (max 860 px), scrolls if needed.

1. **AUDIO**: BACKEND two-position switch ASIO | WASAPI (ASIO disabled with reason when not
   built or no driver) · DEVICE LCD select · BUFFER LCD select (only sizes the device
   supports) · LATENCY LCD `MIDI→BUFFER x · OUTPUT y · TOTAL z ms` · DROPOUTS counter +
   RESET + hint "Raise buffer size" when > 0 · STREAM lamp + state + RECONNECT (live only
   when stopped).
2. **MIDI DEVICES**: table lamp · port · role (LAUNCHPAD / LCXL / OTHER) · status
   (connected / disconnected / port busy / bootloader — run updater).
3. **MIDI LEARN**: this set's bindings `source → target`, × to remove each. Empty: "No
   bindings. Right-click any knob, fader or key → Learn MIDI CC. Pads: LEARN in the pad
   editor."
4. **LOG**: OPEN LOG FOLDER.

### 8.1 MIDI learn interaction

Right-click (or Shift+F10 / Menu key) any on-screen knob, fader or key → **Learn MIDI CC**.
While armed: control outline blinks amber (steady with reduced motion), notice row 1. Next CC
from any device other than Launchpad/LCXL binds. One binding per source: re-using a bound CC
moves it. Bound controls show a 6 px amber dot. LCXL messages are ignored while learning
("LCXL controls are fixed in Part 1"). Pad learn: editor LEARN key or pad menu; next Note On
from an other-device. Esc cancels.

Part 2 gets its own spec; this fixes the look so it fits the console.

```
┌──────┬[PERFORMANCE][PRACTICE][MEMORY] ▮▮▮▯▯ [Funk 01 · 92 BPM · BAR 5/16]   [94% ×2 ★★☆]┐
│ RAIL ├────────┬───────────────── glass display ──────────────────────────────────────┤
│      │ VOLUME │ ▦ RIDE     │   ■        ┃      ■     │     ■         [12 STREAK!]   │
│      │ METRO  │ ▦ HAT      │ ■  ■  ■    ┃ ■  ■  ■    │                              │
│      │ YOU    │ ▦ SNARE    │    ■       ┃    ■       │                              │
│      │ GUIDE  │ ▦ KICK     │ ■     ■    ┃ ■     ■    │                              │
│      │ BACKING│                          ┃ PERFECT                                   │
│      │(◀)(Ⅱ)(↻)                                                                       │
└──────┴────────┴────────────────────────────────────────────────────────────────────┘
```

- Header: interlocked mode keys, 10-segment LED progress bar, lesson LCD (title, BPM, bar;
  Practice adds `TEMPO 70% → 100%`), score LCD (accuracy, multiplier, 3 LED stars).
- Left column 120 px: 4 mini faders METRO / YOU / GUIDE / BACKING; round rubber transport
  BACK (red ring), PAUSE, RESTART.
- Glass display: lane header 120 px = tiny rubber 8×8 map (lane's pad lit in its colour) +
  LCD name. Lane height = display height / lanes, clamped 48–96 px (scroll beyond). Notes:
  26 px glowing blocks moving right → left; pending = hand colour with L/R glyph, hit =
  green, miss = grey + red ×. Playhead amber at ⅓ from the left with a top triangle; bar
  lines faint, beat lines fainter, bar numbers above. Judgement under the playhead (PERFECT /
  EARLY n ms / LATE n ms / MISS). Streak toast top-right, 1.2 s. Practice: loop bracket on a
  bar ruler. Memory: guide notes at low opacity. End: results LCD (stars, accuracy, best
  streak, XP, RETRY / NEXT).

**Reserved slots.** GAMES (Part 3) reuses the Launchpad panel component scaled up as the
game screen. BAND (Part 4) reuses the MIX column component per instrument channel. So in 1B,
build the Launchpad panel and the mixer column as standalone components with a size prop.

## 10. Keyboard

Plain letters and digits are reserved for playing pads.

| Key | Action |
|---|---|
| `1–8`, `Q–I`, `A–K`, `Z–,` | play bottom 4 rows (row 4 → row 1); Play screen only, never while typing; also selects the pad |
| Space | grid focused or nothing focused: play selected pad; browser: audition |
| Enter (browser) | load file into selected pad |
| Arrows | grid: move selection; knob/fader: change value (Shift = fine) |
| PageUp / PageDown | previous / next bank |
| Alt+1–8 | go to bank |
| F2 | rename active bank (Play) or focused group (MIX) |
| Delete | clear selected pad (undoable) |
| Ctrl+B | fold / unfold browser |
| Ctrl+1 / Ctrl+2 / Ctrl+3 / Ctrl+, | PLAY / MIX / TRAIN (inactive in Part 1) / SETUP |
| Ctrl+N / Ctrl+O | new set / open set |
| Ctrl+Z / Ctrl+Y or Ctrl+Shift+Z | undo / redo |
| Shift+F10, Menu key | context menu of the focused control |
| Esc | cancel innermost (drag → learn → rename → menu/popover); if nothing, STOP ALL |

## 11. Accessibility basics

- Focus ring 2 px `--focus`, 2 px offset, `:focus-visible` only, on every control.
- Contrast: silkscreen on body ≈ 5.6:1, LCD text on glass ≈ 15:1 (WCAG AA).
- Grid: `role="grid"`, one Tab stop, arrows inside, `aria-activedescendant`. Pad label
  "Row 4, column 2, KICK_808, mix 4, choke off" / "…, empty" / "…, sample missing".
- Knobs/faders `role="slider"` with `aria-valuetext` ("−3.0 dB"). Latching keys
  `aria-pressed`. Choke/mix/mode rows `radiogroup`. Mode rail `tablist`; blank caps
  `aria-disabled` + label "Games, coming in Part 3". Browser `role="tree"` with
  `aria-activedescendant`.
- Notice LCD `aria-live` (polite; assertive for errors).
- Never colour alone: lamps have printed labels + state tooltips; missing pad shows `!`;
  MUTE/SOLO printed; Train notes carry L/R glyphs.
- `prefers-reduced-motion`: no key transitions, no toast slide, on-screen missing-sample
  blink becomes steady red + `!`, learn blink becomes steady. Hardware unaffected; LED
  mirror still updates.
- Follows Windows display scaling (Tauri).
